# 管理员接口

> 所有管理员接口（登录除外）均需要管理员 session 认证

---

## 1. 管理员认证

### 1.1 管理员登录

#### 1.1.1 基本信息

> 请求路径：/admin/login  
> 请求方式：POST  
> 接口描述：管理员登录验证

#### 1.1.2 请求参数

参数格式：application/json

| 参数名   | 类型   | 是否必须 | 备注         |
|----------|--------|----------|--------------|
| username | string | 是       | 管理员用户名 |
| password | string | 是       | 管理员密码   |

请求参数样例：
```json
{
  "username": "admin",
  "password": "password123"
}
```

#### 1.1.3 响应数据

参数格式：application/json

成功：
```json
{
  "ok": true
}
```

失败：
```json
{
  "error": "用户名或密码错误"
}
```

---

### 1.2 管理员登出

#### 1.2.1 基本信息

> 请求路径：/admin/logout  
> 请求方式：POST  
> 接口描述：管理员登出

#### 1.2.2 请求参数

无

#### 1.2.3 响应数据

参数格式：application/json

```json
{
  "ok": true
}
```

---

### 1.3 获取当前管理员状态

#### 1.3.1 基本信息

> 请求路径：/admin/me  
> 请求方式：GET  
> 接口描述：检查当前管理员登录状态

## 2. 创作者申请管理

### 2.1 获取创作者申请列表

#### 2.1.1 基本信息

> 请求路径：/admin/applications  
> 请求方式：GET  
> 接口描述：获取创作者申请列表，支持按状态筛选

#### 2.1.2 请求参数

参数格式：查询参数

| 参数名 | 类型   | 是否必须 | 备注                                              |
|--------|--------|----------|---------------------------------------------------|
| status | string | 否       | 申请状态：pending(待审核)、approved(已通过)、rejected(已拒绝)、all(全部)，默认 pending |

请求参数样例：
```
/admin/applications?status=pending
/admin/applications?status=all
```

#### 2.1.3 响应数据

参数格式：application/json

```json
{
  "data": [
    {
      "id": 1,
      "user_id": 5,
      "status": "pending",
      "reason": "我想成为创作者，已经发布了多个作品...",
      "platform": "类脑",
      "published_works": "作品A、作品B",
      "admin_note": "",
      "applied_at": "2024-01-10T10:30:00",
      "reviewed_at": null,
      "user": {
        "id": 5,
        "username": "creator_wannabe",
        "discord_id": "123456789012345678",
        "avatar": "abcdef123456",
        "role": "user"
      }
    }
  ]
}
```

---

### 2.2 审批创作者申请

#### 2.2.1 基本信息

> 请求路径：/admin/applications/:id  
> 请求方式：PUT  
> 接口描述：审批创作者申请，通过或拒绝

#### 2.2.2 请求参数

参数格式：路径参数 + application/json

路径参数：

| 参数名 | 类型    | 是否必须 | 备注       |
|--------|---------|----------|------------|
| id     | integer | 是       | 申请记录 ID |

请求体：

| 参数名 | 类型   | 是否必须 | 备注                              |
|--------|--------|----------|-----------------------------------|
| action | string | 是       | 操作类型：approve(通过) 或 reject(拒绝) |
| note   | string | 否       | 管理员备注                        |

请求参数样例：
```json
{
  "action": "approve",
  "note": "作品质量优秀，批准通过"
}
```

#### 2.2.3 响应数据

参数格式：application/json

成功：
```json
{
  "ok": true
}
```

失败：
```json
{
  "error": "action 必须是 approve 或 reject"
}
```
```json
{
  "error": "申请不存在"
}
```

## 3. 用户管理

### 3.1 获取用户列表

#### 3.1.1 基本信息

> 请求路径：/admin/users  
> 请求方式：GET  
> 接口描述：分页获取用户列表，支持用户名搜索

#### 3.1.2 请求参数

参数格式：查询参数

| 参数名 | 类型    | 是否必须 | 备注                       |
|--------|---------|----------|----------------------------|
| page   | integer | 否       | 页码，默认 1               |
| limit  | integer | 否       | 每页条数，默认 20，最大 50 |
| q      | string  | 否       | 用户名模糊搜索             |

请求参数样例：
```
/admin/users?page=1&limit=20&q=test
```

#### 3.1.3 响应数据

参数格式：application/json

```json
{
  "data": [
    {
      "id": 1,
      "discord_id": "123456789012345678",
      "username": "example_user",
      "avatar": "abcdef123456",
      "role": "user",
      "is_banned": false,
      "created_at": "2024-01-10T10:30:00"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 100,
    "totalPages": 5
  }
}
```
